Quick Language Switcher

Switch languages without opening Preferences.

One click instead of five

Changing the interface language normally means opening Settings → Users & Companies → Users → Preferences → Language, saving, and reloading. This module puts a globe in the top bar instead: click it, pick a language, and the back end reloads fully translated.

Everyone can do it — no administrator rights, no technical settings, no access to the Users menu required.

Main benefits

Fast access The selector sits in the systray, next to the company and user menus. It is always one click away, on every screen. Active languages detected automatically The list comes straight from your res.lang records. Install a language and it shows up; archive it and it disappears. Nothing is hardcoded.
Simple back end integration A standard systray entry and two small ORM methods. No core patching, no overridden views, no new models, no extra access rights. Community + Enterprise Built against Community APIs and depending only on base and web, so it drops into either edition without changing the navbar theme.
Responsive and right-to-left ready Icon only on phones, icon and language name on wide screens. Arabic and other RTL languages are handled by Odoo itself — the component never forces a direction and uses logical CSS properties only. Odoo 17 / 18 / 19 A dedicated package per series, each using the native component API of its Odoo release rather than runtime version detection.

How it works

  1. Install at least two languages in Odoo.
  2. Install this module — nothing else to configure.
  3. Click the globe in the top bar and choose a language.
  4. The server validates the choice, stores it on your own user record, and the web client reloads translated.

With more than ten active languages, a search box appears at the top of the dropdown so you can filter by name or by code. With a single active language the switcher hides itself, because there is nothing to switch to.

Security by design

The endpoint takes a language code and nothing else. There is no user id parameter, so it can only ever write the language of the person calling it. The code is validated server-side against the installed, active languages before anything is stored, and the module never elevates privileges.
